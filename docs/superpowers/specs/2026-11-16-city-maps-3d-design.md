# 나라·도시 맵 + 캐주얼 3D 전환 설계

날짜: 2026-11-16

## 의도

34개월 아이가 롤러 위에서 밸런스바이크를 타며 TV를 본다. 지금은 테마 코스 5개(숲속길 등)를 2D 캔버스 가짜 3D로 그린다. 이것을 **실제 도시를 달리는 캐주얼 3D 세계**로 바꾼다. 아이는 멀리 보이는 큰 명소를 향해 달리고, 가까워지고, 옆을 지나거나 통과한다. 주변은 살아 움직인다. 부모는 옆에서 "남산타워다!" 하고 말해줄 수 있다.

## 목표

- 나라 선택 → 도시 선택 2단계. 나라 3, 도시 12.
- 도시마다 실제 명소가 **실제 모양·비율·색을 닮게** 나온다. 화풍은 캐주얼 3D(단순한 면, 밝은 색).
- 화면 전체가 진짜 3D: 길, 지형, 명소, 소품, 캐릭터.
- 배경에 움직이는 것이 항상 보인다: 바람, 새·나비, 기차, 응원하는 사람들 등.
- 기존 기능 유지: 동물 친구(NPC), 친구 방, 속도 입력(자동/누르기/센서), 별 모으기, 100m 응원, 결과 화면, 후방 쿼터뷰.

## 비목표

- 실제 지도·도로망 재현. 명소 사이 실제 거리와 방향은 따르지 않는다.
- 조향, 충돌, 갈림길.
- 기존 5개 코스 유지. 삭제한다.
- 밤 배경, 날씨 변화 선택.
- 휴대폰 화면 최적화 (TV·PC 브라우저 대상).

## 반목표 (되면 실패)

- 무섭거나 어두운 화면, 빠른 깜빡임.
- TV에서 끊김. 목표 1080p 60fps, 최저 30fps.
- 도시 진입 로딩 3초 초과.
- 실제 상표·로고 노출 (도톤보리 간판, 타임스스퀘어 광고는 형태만, 글자·로고 없음).
- 인터넷 없으면 안 돌아감. 라이브러리는 로컬에서 제공.

## 방식 (검토한 것)

| 방식 | 내용 | 장단점 |
| --- | --- | --- |
| A. 전부 코드 | 명소를 기본 도형 조합으로 조립 | 가볍고 통일감, 비용 0. 디테일 많은 명소는 닮음 한계 |
| B. 전부 모델 파일 | 명소 약 48개를 받거나 AI 생성 | 가장 닮음. 화풍·품질 제각각, 용량·로딩, 라이선스, 크레딧 |
| **C. 섞기 (선택)** | 전부 코드로 먼저 완성, 디테일 중요한 대표 명소만 모델 파일로 교체 | 닮음 필요한 곳만 비용. 교체 명소는 화풍 손질 필요 |

사용자가 C 선택. 이유: 닮음 요구를 채우면서 12개 도시를 한 번에 돌릴 수 있고, 화면을 본 뒤 교체 대상을 정할 수 있다.

**이 설계 범위 = 1차**: 전부 코드로 12개 도시 완성 + 모델 파일을 끼울 자리. **2차(별도 요청)**: 화면을 보고 사용자가 고른 명소를 모델 파일로 교체.

## 화면에서 겪는 것

- **설정 화면**: "코스" 자리에 나라 버튼 3개(국기 + 이름) → 고른 나라의 도시 카드. 카드 그림은 그 도시 대표 명소를 3D로 한 번 그려 만든 축소 그림. 메뉴 뒤 배경은 지금처럼 고른 도시를 천천히 날아가는 화면.
- **주행**: 명소가 멀리서부터 보이고 달릴수록 커진다. 명소 옆을 지날 때 이름을 크게 띄우고 효과음 (기존 100m 응원과 같은 방식). 설계자 제안.
- **거리**: 200m·400m·800m 어느 것이든 명소 4개가 코스 길이의 약 20%, 40%, 60%, 85% 지점에 온다.
- **크기**: 명소 하나 안에서는 실제 비율을 지킨다. 명소끼리는 실제 크기 차이를 줄인다 (탑이 문보다 30배 크면 문이 안 보이므로). 설계자 판단.

## 구조

**기술 선택 (설계자 판단)**
- three.js를 npm으로 설치, `server.js`가 로컬에서 제공. CDN 없음. 빌드 도구 없음, 지금처럼 브라우저 모듈 그대로.
- 그림자는 실시간 그림자 대신 바닥의 둥근 그림자. 재질은 단순 조명 재질. 반복 소품은 인스턴싱. 먼 곳은 안개로 가림.

**재사용**: `game.js`의 주행·NPC·순위·별·네트워크, `input.js`, `net.js`, `audio.js`, `main.js`의 화면 흐름, `sprites.js`의 캐릭터 목록과 메뉴용 얼굴 그림.

**교체**
| 지금 | 바뀌는 것 |
| --- | --- |
| `render.js` (2D 캔버스) | three.js 렌더러. `render(scene)`, `resize()` 같은 모양 유지 → `main.js` 변경 최소 |
| `courses.js` (테마 5개) | 도시 데이터: 나라, 도시, 색, 명소 목록과 위치, 길가 규칙, 움직임 규칙 |
| `sprites.js`의 소품·주행 캐릭터 그림 | 3D 소품, 자전거 탄 3D 동물 캐릭터 (기존 8종, 같은 색) |
| `game.js`의 길가 소품 배치 | 도시 데이터 기반 배치. 굽은 길은 실제 3D 경로로 계산 |
| `main.js`의 색종이·이름표 2D 그리기 | 3D 화면 위에 겹치는 방식으로 옮김 |

**새 단위와 책임**
- 도시 데이터: 무엇이 어디에 나오는지. 그리는 코드 없음.
- 경로: 굽은 길의 3D 중심선. 거리 → 위치·방향.
- 명소: 명소 하나 = 3D 덩어리 하나를 돌려주는 조립 함수. 나라별 파일.
- 소품: 나무, 집, 사람, 탈것 등 여러 도시가 같이 쓰는 것.
- 움직임: 새·나비, 기차·탈것, 응원 인파, 바람, 흩날리는 것(꽃잎·눈·낙엽). 시간으로만 움직이고 주행 로직과 무관.
- 캐릭터: 자전거 탄 동물, 발 구르기와 기울기.
- 세계 조립: 도시 데이터 + 경로 → 장면. 카메라 주변 구간만 유지.

**모델 파일 자리**: 명소마다 "모델 파일 경로(선택)"를 가진다. 파일이 있으면 그것을, 없으면 코드 조립을 쓴다. 1차에서는 파일 없이 전부 코드. 불러오는 코드와 폴더 규칙만 마련한다.

**설정과 서버**
- 설정값 `course`에 도시 id를 넣는다 (`seoul`, `sanfrancisco` 등 소문자 12자 이내 → 서버 검증 정규식 그대로 통과). 서버 기본값만 `forest` → `seoul`. 나라는 도시에서 역으로 찾는다.
- 저장된 옛 코스 id(`forest` 등)는 서울로 대체.
- 배경 음악은 기존 5곡을 도시에 나눠 배정.

## 닮음 기준

명소마다 "이것만은 맞아야 하는 특징" 3~5개를 도시 데이터 옆에 적고 그대로 만든다. 예:
- N서울타워: 산 위, 흰 기둥, 위쪽 원통 전망대, 붉은·흰 줄무늬 안테나.
- 금문교: 인터내셔널 오렌지색, 2개 주탑(가로대 4단), 늘어진 주 케이블과 세로 줄.
- 첨성대: 병 모양 곡선, 가운데 네모 창, 위 정(井)자 돌.
- 도쿄타워: 붉은색·흰색 띠, 아래로 벌어진 4다리 격자, 2단 전망대.

사진과 나란히 놓고 윤곽과 색이 바로 알아봐지면 통과. 통과 못 하는 명소는 2차 모델 교체 후보로 사용자에게 보고.

## 확인 방법

- 계산 로직(경로, 배치, 도시 데이터 검증: 12개 도시 모두 명소 4개·id 규칙·필수 값)은 자동 테스트.
- 화면은 브라우저로 12개 도시를 실제로 띄워 명소별 화면을 찍어 확인. 프레임 속도 측정.
- 친구 방: 브라우저 2개로 같은 도시가 보이는지 확인.

## 만드는 사람에게 맡기는 것

- 파일 나누기 세부, 함수 이름, 삼각형·호출 수 예산의 구체 값.
- 굽은 길을 3D 경로로 바꾸는 계산식과 굽은 정도.
- 명소별 세부 조립, 색 팔레트 값, 길가 소품 밀도.
- 도시 카드 축소 그림 만드는 시점(시작 때 한꺼번에 또는 필요할 때).
- 만드는 순서. 권장: 3D 기반(길·캐릭터·서울 한 도시) 먼저 돌려보고 → 움직임 → 나머지 도시.
